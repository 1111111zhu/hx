# 配对交付：从新闻来源到 PPTX 与 XLSX

## 默认结果与模板

用户说“更新周报行业新闻”“做本周 P23-24”或要求图二式成果时，默认交付可下载的 `.pptx` 和 `.xlsx`，不能以 JSON、Markdown、新闻清单或操作建议结束。仅明确要求筛选、诊断或规则编辑时不生成配对报告。

优先使用本次附件中的匹配模板；没有新附件时使用本 Skill 的 `assets/templates/weekly-template.pptx` 与 `evidence-template.xlsx`。两份内置文件取自用户图二对应的 20260829–20260904 不重叠配对版，仅是历史版式基线，其中行业新闻尚未更新，不得沿用为本周事实。不要混用不同版本的 PPT 和 Excel。用户提供新模板时覆盖本次模板选择，不必修改安装包。

## 环境与执行

所有路径相对于当前 Skill 或本次工作目录，不依赖作者的用户名、浏览器会话、桌面路径或其他已安装 Skill。Python 3 标准库可运行 `scripts/通用/配对产物.py` 做模板初始化、原生表格定位和交付结构检查。文件实际编辑可使用当前环境提供的工具，或 Python 的 `python-pptx`、`lxml`、`Pillow`；复杂工作簿优先对目标 OOXML 部件定点修改，避免库重存丢失外链、图表、样式与绘图。源网页访问和 PPT/Excel 渲染需要当前智能体的浏览器/API与 Office 或 LibreOffice 等能力。不能假设仅安装 Skill 就获得来源权限或渲染程序。

先运行 `python scripts/通用/配对产物.py --help`，再执行：

```sh
python scripts/通用/配对产物.py prepare --output-dir ./weekly-work
```

若提供新模板，额外传 `--pptx /path/template.pptx --xlsx /path/template.xlsx`。输出为工作副本及 `pair_inventory.json`；此时状态仅为 `prepared`，不是更新完成。

## 制作顺序

1. 明确周区间和更新范围，核验候选原文、账号、时间与直链。筛选脚本只帮助排序，不证明源网页已经核验。保存每条原始首段和来源记录。不得把缺阅读量当成障碍。
2. 通过可见标题 `近期行业要闻梳理` 定位两张目标幻灯片，通过表头与列数识别原生表格。不要把工作表名中的 P23-24 当作 PPT 绝对页码。库存清单列出 slide XML、表格索引和表头作为定位辅助。
3. 使用同一份已核验 items 按时间倒序填入原生表格的日期、概述等对应列。行业新闻日期列使用医药魔方Info第一段里的日期并只写月日，不能使用文章发布日期，也不能给事件日期补年份；正文列不额外加日期，若首段开头日期已抽到日期列，只删除该开头日期标记并保留后续原文；只删除含 `以下简称` 的括号段，其他括号内容保留。保持字体、字号、表格宽度、颜色、对齐、页脚和来源栏。不能整页换成图片。先尝试模板允许的行高调整/行分配；若长文溢出仍无法容纳，明确报告版式限制，不删字、不用省略号、不遮盖页脚。
4. 删除已替换目标表格中未使用的旧周正文与日期；不足十条时保留真实新条目并报告缺口。只更新指定阶段，非目标页与工作表保持基线。
5. 保存 PPTX，再渲染目标页。以最终表格每行实际像素边界机械裁剪左证据图，必须完整包含末字和标点。不能重新打字模拟行截图，不能沿用旧左图。保存 `item_id → slide/table/row → left_crop` 映射。
6. 从真实来源捕获右图：文章标题、医药魔方Info、发布时间和完整首段，裁至首段下方黑线（如存在），不含后续内容。多张图分开保存，记录 `source_images[]`，不能拼接。
7. 更新 `P23-24行业新闻` 的对应证据块，清理旧图片对象和旧链接关系。A:J 左图，K 紫色间隔，L 起右侧来源 URL 和原文图；URL 位于白色首行，显示文本和超链接完全相同。每条右图有两张时依实际高度依次放置并留至少 12 px；下一个证据块的位置根据本块最大图像下界计算。移动紫框/分隔边界适应图片，不能复用导致重叠的锚点或压扁截图。细节见 `references/通用规则/证据版式质检.md`。
8. 重新打开保存后的两份文件，核对条目顺序、全文一致、链接、图片数和坐标；渲染目标页和证据表逐项查看。核验旧新闻确实已替换、所有图互不相交、左图来自最终 PPT 行。
9. 执行 `python scripts/通用/配对产物.py check --baseline-dir ./weekly-work --pptx /path/final.pptx --xlsx /path/final.xlsx --items /path/weekly_news.json`。此工具仅检查包完整性、原生正文是否写入、Excel 超链接和文件是否有变动，不能代替视觉与来源核验。

## 交付与阻塞

最终回复先给两个真实文件链接：`华鑫医药周报_YYYYMMDD-YYYYMMDD_更新版.pptx` 和 `华鑫医药周报底稿_YYYYMMDD-YYYYMMDD_更新版.xlsx`。附周区间、条数、已更新范围及未完成项。JSON/清单作为辅助文件，不抢占主要交付位置。

记录 content、ppt、excel、evidence、visual_qa 五项状态。只有全部检查通过才为 `completed`；结构检查通过不等于视觉检查通过。正文已完成而截图缺失时仍生成并交付标为 `_部分更新` 的工作副本，明确缺哪条证据，绝不把旧图保留为新证据。来源完全不可核验时报告 `blocked_source`，不把模板副本作为已更新成果。模板缺失、无法编辑或无法渲染时指出具体依赖及完成程度，不静默退化成清单。
